# AutoHub

Windows desktop app (PySide6) that automates the ECU variant workflow: it reads
the Master Sheet, ECU Info Sheet and System Matrix Excel files, manages variant
rows in the Master Sheet, and creates and fills WebFlow jobs through browser
automation. Each feature is a module plugged into the main window sidebar.

## Features

### Main window

- Fixed-size window (1024x700) with a dark theme and dark title bar.
- Startup dialog: a themed loading card (logo, version, current step, progress bar) appears immediately at launch while AutoHub applies settings and logging, prepares the interface, loads modules and configuration, builds the main window, and loads the remembered Master Sheet's variants. The dialog opens on the monitor under the mouse (otherwise the primary monitor), and the main window opens centered on that same monitor. Each step is logged. If a step fails, the dialog closes and an error message explains why AutoHub could not start.
- Collapsible sidebar (220px to 56px icon-only) with the logo and Home / Creation / Form B / Comparison navigation.
- The window title shows the active module.
- Cross-module wiring: variants loaded on Home are passed to Creation, Form B and Comparison automatically.
- **Calibration upload**: WebFlow creation clicks the Calibration file row's **+** button in Files > Request Files before uploading the variant's CAL HEX from the remembered calibration folder. Selenium supplies the file directly without opening an OS file chooser.
- Reloading Home or loading another Master Sheet replaces Creation and Form B data and WebFlow links, including cleared links; links from the previous load are not retained. Save Home edits with Update Master Sheet before creating jobs.
- All external job links open on double-click only, in Home, Creation and Form B. Single-click does not open a browser.
- On close, pages that hold resources (the WebFlow browser session) are shut down.
- WebFlow job filling reads each drop-down list in one query (no per-option waits, no option cap) and confirms the "Saved successfully" toast after Save; an error toast or no toast fails the job with a clear log line.
- Job creation stops before submission if a form selection fails. If WebFlow replaces the Confirm button or loading indicator during an Angular refresh, automation re-finds it within the existing timeout; a successful submission is never retried.
- **Save before import/picking**: AutoHub saves the current job before Import from Race (after filling Hardware part number), Import from pool, ECR Import and Pick PST_Lib. An enabled Save must show the successful-save confirmation before the next action; a disabled Save means there are no changes to save. A failed Save stops the workflow before the action and does not consume a pool/ECR import attempt. The final Save after ECU and Customer filling remains unchanged.
- **Save-before-import warning**: if the dialog says “Data filled in by you will be saved before import. Do you want to continue?”, AutoHub clicks **Yes** once during Import from Race, Import from pool, ECR Import or Pick PST_Lib and waits for the warning to close. Unrelated warnings are never confirmed automatically.
- **Save button and Job information**: a gray/disabled Save is skipped without clicking. After an enabled Save is confirmed successful, AutoHub collapses Job information again before continuing; failed saves do not trigger collapse.
- **After import/picking**: AutoHub also collapses Job information after Import from Race, Import from pool, ECR Import and Pick PST_Lib complete successfully, before continuing. A failed action does not trigger collapse.
- **Race import reuse**: if Classification's Product release state already has a value (for example `40: Series`), Import from Race is skipped. Blank states, including WebFlow's `---` placeholder, still trigger the import.
- **PST_Lib reuse**: Pick PST_Lib is skipped when Program identification complete matches the requested PVER (ignoring revision) and PST_Lib Container matches that identification, including its revision. Blank or mismatched fields still trigger the picker.
- **Unchanged fields**: before filling General, ECU, and Customer fields, AutoHub compares the current value and skips matching text, dropdowns, and checkboxes. Multi-selects compare the complete selection regardless of order, including supported sheet aliases; matching selections are left unchanged even when disabled.
- **Success popups**: after Save is confirmed or an import/picking action completes, AutoHub closes all visible success notifications, including “Saved successfully” and “Imported successfully”, using their Close buttons. Warnings, errors and informational messages remain untouched.
- **Browser window**: Edge is maximized automatically when each browser session starts.
- **Enabled imports only**: import and PST_Lib buttons are clicked only when enabled, including native, ARIA and gray/disabled class states. A disabled button is not clicked; if it does not become available within the existing timeout, the action fails explicitly.
- **Page readiness**: automation waits for both activity indicators and loading overlays. Save scrolls its control into view and re-finds it if a stale element or intercepted click prevented submission; an uncertain or successful submission is not repeated. An earlier “Imported successfully” toast does not replace the required save confirmation. Job information collapse waits for idle and verifies the collapsed state; General multiselects scroll into view before opening.
- **Matching field values**: before editing a text input or textarea, AutoHub reads its current WebFlow value and skips typing when it matches exactly, including read-only fields. Dropdowns and checkboxes preserve matching selections; multiselects click only options whose selected state differs. Skipping a field edit does not skip separately requested import actions.
- WebFlow-controlled checkboxes that are disabled for a variant are left unchanged; any requested values that could not be applied are listed in the job-creation completion summary.
- Every WebFlow step also records the page for analysis in `logs/webflow_trace/<timestamp>/` (`NNN_step_OK|FAILED|ERROR.html`, `.png` screenshot, `.json` list of every input, select, button, link and label with id, class, text, state and CSS path, `NNN_step_OK.changes.json` with every DOM change (added / removed elements, attribute and text changes) and every fetch / XHR request (method, url, status, ms) that happened while the step ran, plus `index.jsonl` with url, title, outcome, duration, change / request counts and whether the page was reloaded); turn it off with **Analysis** in the Settings module.
- Logging to `logs/autohub.log` and the console, including every WebFlow creation step (browser start, dashboard, form fields, each tab field, save, job ids, link writing) with its outcome and duration; every step names the value it sets (e.g. `General: limitations = NO`, `(empty)` / `(none)` for blank values) and each job first logs one `Values to fill` line with all its General / ECU / Customer values; turn it off or on with the **Logging** checkbox in the Settings module (saved as `logging_enabled`, applied with **Apply**, default on).
- User settings are persisted to `%APPDATA%/AutoHub/settings.json`: file paths and WebFlow config.
- Settings > Diagnostics > Logging includes **Open log file** (opens `logs/autohub.log` in the default application) and **Clear log content** (asks for confirmation, then clears the file without stopping logging). These actions run immediately without Apply.

### Home module

- **Load Master Sheet** validates the selected workbook before remembering it as the active Master Sheet or loading any variants. Validation uses the shared format checker: a readable workbook (password-protected or not), the supported MG1 `Master sheet` or Mx17 `ECU Container Release Honda GDI` sheet, and the required mapped column headers/identity markers in that layout. Unsaved changes are confirmed before replacing a selection. An invalid selection shows its validation error, clears the active sheet and associated variants (including downstream Creation/Comparison data), and leaves variant actions disabled. Load variants reloads a validated active sheet.
- **Validation prerequisite**: without a successfully validated Master Sheet, **Load variants**, **New variants**, table editing, **Update Master Sheet**, Clear and Delete are disabled and the table is empty. Validation is repeated before loading, computing or saving variants and before accepting background results; it is never inferred just from a saved/existing path. The active file is watched for changes or removal. Failed re-validation clears its remembered path, rows, cached variants, edits and pending deletions, disables the workspace, and reports the error. A new valid selection restores the existing workspace workflow. While an operation runs, conflicting workspace actions are disabled; stale results cannot restore invalidated rows.
- **Load at startup**: a remembered Master Sheet must pass the same structure validation before its actions are enabled and its variants load inside the startup dialog. Validation reads the workbook without Excel and decrypts protected workbooks in memory. Missing or invalid selections are cleared and logged without blocking startup; use Load Master Sheet to choose a valid file. A transient variant-read error is logged and leaves the validated sheet available for retry.
- **New variant**:
  - Prompts for the ECU Info Sheet CR and System Matrix CR.
  - Hover tooltip: "Create new variant by reading ECU Info Sheet CR and System Matrix CR."
  - Reads all three files through Excel COM automation on a background thread.
  - Computes variants that are not yet in the Master Sheet. Nothing is written at this step.
  - Fails with a clear message if the files are inconsistent, for example Main/Container/Boot counts that don't match, or a part number missing from the System Matrix.
- **Derived columns**: ECU HW Name equals ECU Type; TP Level is `TP9` when the ECU Info Sheet's ROM Check and Tuning Protection are both ACTIVE, otherwise `TP3`; Engine Family is read from the ECU Info Sheet's `1) Issue CR` sheet (the entry marked YES, e.g. `NP1`).
- **Project Purpose**: new variants use `<Project> - <Event>_<MP>` from the ECU Info Sheet's Event and MP No., for example `6WZX - CERT_MP0` (just `<Project> - <Event>` without an MP). Existing values are not rewritten; duplicate detection, Creation event filtering and ECR notes read the older `<Project> - <Event> Lot / <MP>` and `<Project> for <Event>/<MP> event` formats as the same `<Event>_<MP>`.
- **SecuAcs_CustTypeI**: new variants with ECU hardware `MG1CS022` always use `FFFFFFFFFFFF`, overriding the Boot sheet's security value. Other hardware uses the Boot sheet's SK1/SK2/SK3 values joined in order, leaving the field unset when they are missing. Existing Master Sheet rows are not rewritten.
- **General-info list values**: Model year, Emission norm, Transmission, Immobilizer and Market resolve to the actual WebFlow list labels. Examples: `MY27` → `2027`, `Bharat Stage 6` → `BS6`, `manual` → `MT`, `Active|IMMO 6` → `active|IMMO6`, and `UK` → `GB`. Exact list items win; combined items such as `AT / MT` stay intact when offered, otherwise slash/comma/semicolon-separated values resolve individually. Unknown or ambiguous values stop the fill with the available options logged; emission-stage/RDE qualifiers are not silently dropped and unsupported countries are not replaced by a guessed region. Canonical spellings apply to newly computed variants and loaded WebFlow payloads without rewriting existing sheet cells.
- **Job-loading checks**: opening an existing or resumed job waits for the WebFlow title, initial loading screen to disappear, activity to finish, and the General tab to become visible. If Edge shows `ERR_UNEXPECTED`, AutoHub refreshes the job page up to the WebFlow refresh-attempt limit; a persistent error closes the browser and fails the open, and existing batch retry/resume safeguards retain known job IDs. A dashboard that still fails to load after its refresh limit also closes the browser. Classification scrolls each unset checkbox into view and waits until it is clickable before cycling to X (false), checking the final state and rejecting disabled controls.
- **SW Version / Indi Spec**: SW Version is `01` for ECU type MG1CS022 only, otherwise `-`; Indi Spec (e.g. `Honda_MG1CS022_CS_IndiSpec_01`) is filled in the table and the WebFlow job uses that cell.
- **PST_Lib selection**: Program version (PVER) from Master Sheet column `AY` searches the WebFlow **Pick PST_Lib** dialog's Program Identification column. Sheet values such as `MG1CS022_62XSC_V020_CS` match WebFlow's `MG1CS022_62XSC/V020_CS;0` format, ignoring only the revision suffix. The job proceeds only when exactly one row matches; the matched row is selected with **Pick PST**.
- **WebFlow values**: all mapped job values come from the loaded Master Sheet, not hard-coded defaults: ECU Generation / Brand / ECU Type (`Q` / `R` / `S`), General (`T`–`AA`), Hardware/Plant (`AB`–`AZ`), ECU (`BC`–`BG`) and Customer (`BH`, `CL`–`CN`, `CQ`, `CR`). Blank optional cells are skipped except checkbox cells, which default to False (X); blank required creation fields stop submission. Checkbox cells accept Yes/No, True/False, 1/0 or X (checked). TP Level `TP3` / `TP9` maps to the WebFlow option `3` / `9`; multi-select cells use `|` between values. Tool version, routing, customer group and working mode remain configuration because they have no mapped sheet columns. The configured tool version may be shortened: `PD W0002` selects WebFlow's `PD W0002 (Productive)` (an exact option wins; matching ignores case and spacing, needs whole words, and stops with an error if several options match). Selected variants must share ECU Generation, Brand and ECU Type. Reload variants after changing the sheet, or use Update Master Sheet to save Home edits before creating jobs.
- **Additional WebFlow fields**: Hardware/Plant automation includes vehicle model, engine family, power, emissions, immobilizer, transmission, displacement, market, model year, cylinders, project numbers, hardware/customer/software identifiers, car, customer name, lead plant, ECR number, PVER and data version. Nonblank columns without a matching control in the recorded form (e.g. DWG NO., ECU ID., CALIB ID., boot ID, security authentication fields, EC/EU-MARK and SS-ID) are ignored and not shown. Missing dropdown options and values that do not stick fail the fill step.
- **Total WebFlow time**: the completion or failure dialog and log show elapsed seconds for the entire operation, including browser startup, job creation, filling, saving and link writing.
- **WebFlow fill order**: Delivery Type, Release class, Release scope, Limitations, Safety Monitoring SW by RB, Safety Calibration responsibility, Bosch Cal Data Responsibility, Data Integration responsibility, Hardware part number, Import from Race in Classification, Development number, then Lead Plant. Race import is clicked only after the hardware part number is successfully filled; blank hardware part numbers skip the import. Remaining General fields follow the form top to bottom, followed by ECU, Customer and Save. Blank optional fields are skipped without changing the order.
- **Nonblank checkboxes**: blank Master Sheet checkbox cells (`X`–`AA`) default to False (X), rather than being skipped. From a blank WebFlow control, True takes one click and False takes two sequential clicks. State is verified using the displayed icon because WebFlow reports `aria-checked="false"` for both blank and X; a disabled blank checkbox fails the step.
- **General-tab panels**: controls are located inside their actual panels: General info, Bosch logistic info, Customer logistic info, Ident Numbers and ECR Information. Hardware part number / Development number belong to Bosch logistic info; Lead Plant belongs to Ident Numbers, not Hardware/Plant information. Mappings are checked against the recorded browser form and both filled-job XML samples; sample values never override the Master Sheet.
- **Software part number**: immediately after selecting Lead Plant, click Import from pool once and wait up to the WebFlow timeout for a nonblank, nonzero software part number. The imported value is logged and is not overwritten by Master Sheet column `AX`. A disabled button or failed import fails the job-fill step.
- **Before Lead Plant**: set Classification's Number of variants to `1`, Time limitation required? to `X` (false), and Successor to Time Limited Delivery ECU? to `X` (false). These are explicit workflow values, not sheet defaults. Lead Plant selection waits up to the WebFlow timeout for its popup options to load, including the requested plant.
- **Lead Plant visibility**: scroll the control to the center of the form before clicking its dropdown trigger, read only visible popup options, and verify the selected plant before continuing. Pool import also scrolls its button into view before the single allocation click.
- **Pool button scope**: find Import from pool only inside the Ident Numbers panel containing Lead Plant and Software part number, never by a page-wide button search.
- **Pool import confirmation**: if WebFlow warns that entered data will be saved before import, click Yes once in that warning dialog, then wait for the imported software part number. Unrelated dialogs are not confirmed automatically.
- **Allocated software number**: read the Software part number already in WebFlow before pool import; a nonblank, nonzero number is reused without importing again. Copy it into Software name and Customer software part number, overriding the sheet's customer software number for pool imports. Retain it per variant even if a later copy fails, retry copying without allocating again, and return it as `SoftwarePartNumber` with the job result. Matching destination values are left unchanged.
- **MG1 software number formula**: when the request row's AX cell references K on the same row (`=K59`, for example), write the imported software number into K and preserve the AX formula. Unexpected formulas, including formulas in K, are rejected rather than overwritten.
- **ECR import**: configure Change engineer (Outlook Display Name), Cost allocation and Change Reason in Settings > Creation. Change Reason must match the WebFlow options (`|` separates multiple reasons). With all three settings blank, the previous workflow is unchanged; once any is configured, all three are required before opening the browser. ECR notes are generated for each job from its Project Purpose as `This container is for {project} {event name} event.` (e.g. `This container is for 6WZX CERT_MP0 event.`); a variant whose Project Purpose has no recognizable project and event stops the run before the browser opens. After PST_Lib selection, fill the ECR Information panel, save the job and click **ECR Import** once; if the known save-before-import warning appears, confirm Yes once. Wait for a nonblank, nonzero ECR number; any fill/import failure stops before the final Save. The imported number replaces the sheet's read-only ECR number for this workflow, is retained per variant as `imported_ecr_number` even if a later step fails, and is returned as `ECRNumber` for Master Sheet write-back after successful job completion. ISIR, release-by and compliance controls are left unchanged.
- **New variant source files**: one dialog asks for the ECU Info Sheet and System Matrix (required) and the HW Info and Kick Off Meeting (optional), each with a Browse button. The dialog always starts empty (the chosen files are not remembered). OK is enabled once the required files exist.
- **Mx17 Master Sheet**: a workbook with the sheet `ECU Container Release Honda GDI` (e.g. `Honda_GDI_container_release_info_latest.xlsx`) is detected automatically and handled by `Mx17MasterSheet`; MG1 workbooks use the unchanged MG1 code. Variants are read from the flat main sheet (one row per part number, from row 7) and overlaid with their `*_Info` sheet row. New variants append a main row and a row in an Info sheet named `<project>_Info` (created from `Mx17_5xFx_Info` when missing). Update writes only the cells you changed (to the main sheet and, when the variant has one, its Info row; Info-only fields create an Info row); fields with no column in this layout are reported after Update. Variants that were not changed are not touched. Delete finds the variant by part number (never by a remembered row number) and removes that main row only; no worksheet is ever deleted or renamed, and Info rows stay. Not mapped (left blank for new rows): TP level, TPROT, ENG, Info released-by/cost allocation, PVER, lead plant. Excel COM paths are untested without Excel.
- **Column widths**: every Home table column is kept between 60 and 300 px, both when fitted to content and when dragged (`modules/home/column_limits.py`).
- **Home workspace**: a compact heading replaces the large banner, leaving more room for the table. The Master Sheet card groups file selection and loading; New variants sits beside the table heading. A live summary shows loaded and selected row counts. Clear/Delete remain separate from Update Master Sheet.
- **Latest variants**: Settings module > **Home** > *Latest variants* (5, 10, 20, 50, 100, All) sets how many of the newest variants *Load variants* shows (the last rows of the sheet; *All* = no limit). Apply refreshes the table from the last Load, asking first if the table has unsaved changes. It is saved in `settings.json` (`latest_variant_count`). WebFlow still gets every variant.
- **Delete variants**: select one or more rows (Ctrl/Shift-click) and click *Delete selected* (after a confirmation). They leave the table at once; *Update Master Sheet* then also deletes their REQ/IMPL/comparison rows from the Master Sheet. Each variant is found by its part number right before deleting (never by a remembered row number), so a moved row can never take another variant with it; rows never saved there are just dropped. Deletions are discarded by Clear or a reload.
- **Confirmations**: the Clear button and the Update Master Sheet button each ask "Are you sure?" before acting when the table has variants.
- **Existing rows**: New variants and Load variants both ask when the table holds variants: **Clear** replaces them with the new/loaded ones, **Keep** leaves them and adds the new ones below (skipping ones already there, pending deletions are kept), **Cancel** stops the action. Nothing is removed until the new rows arrive, so a failed action never loses the table.
- **Progress window**: New variant, Load variants and Update show a window with each step, then the result (e.g. `Found 3 new variants`, `Loaded 12 variants`) or the error. It can only be closed once the action has finished or failed.
- **Market** is built from the System Matrix destination codes (`KJ` -> Japan, `KE/KG` -> `UK|Germany/Greece/...`) using the table in `core/markets.py`; unknown codes are kept as written.
- **Model Year** is a four-digit year (`27.0MY`, `MY28` or `19` become `2027`, `2028`, `2019`).
- **List-box columns**: Lead Plant (RtW2, SaW, SiP_test), Delivery Type, Release Class, Release Scope, Limitations and the four Yes/No columns (Safety Monitoring SW, Safety Calibration, Cal Data and Data Integration responsibility) are drop-downs in the table, with the same options as the webFLOW Configurator (`core/variant_choices.py`).
- **Kick Off Meeting (optional)**: New variant can also read a Kick Off Meeting `.pptx` (password `honda` or `hb` is tried when encrypted) and fills Power (kW), Num. of Cylinder (also from "4-cylinder engine" text) and Engine Family (when the ECU Info Sheet CR has none) where those columns are blank, Displacement (cc to litres, e.g. 1199 cc -> 1.2; a System Matrix value is never changed), and corrects Emission (the deck's EM Category, e.g. `BS6 + RDE`, replaces a System Matrix value that means the same norm such as `BS6`; a different norm like EURO 5 is kept) and Immobilizer (`Active|IMMO6`).
- **Load variants**: reads the existing variant rows from the Master Sheet.
- **Editable variant table**:
  - Shows the Master Sheet request columns.
  - Cells can be edited in place.
  - Click a column header/funnel icon (or right-click the header) to filter by text and/or values; filters combine across columns. Funnel icons are subtle gray when inactive and accent blue when active, including frozen columns. Tooltips show "Filter <Column Name>" or "Filter active - click to modify". Hidden rows are still considered on update.
  - "Update Master Sheet" is enabled only after a user edit.
- **Update Master Sheet**:
  - Only changed existing rows are updated; the confirmation lists each affected Part Number. Changes to any field in a row qualify.
  - New rows are inserted from the variant template and stamped with the created date.
  - The table is then reloaded from the sheet.
- After Create/Load/Update, the WebFlow-ready variant list is sent to the Creation and Form B pages.
- Results and errors are shown in message boxes. Button text shows progress.
- **New variants defaults**: edit the default ECU, General, ID, customer and security values in **Settings → Creation → New variants**. The existing values are the defaults; values supplied by the source files remain authoritative.

### Creation module

- Variant checklist:
  - Fed from Home.
  - Read-only grid table with a separate Select checkbox column, followed by Part Number, Family Name, FSWID Project Version, FSWID Program Version and WebFlow Link. Version values come from the same ECU data used to fill the WebFlow job. No variant count is shown above the table.
  - Event labels combine the project version and event from Project Purpose (e.g. `6WZX - CERT_MP0`), supporting the current and older purpose formats. Different projects with the same event remain separate filter options.
  - The event filter defaults to the latest variant's group by created date (or the last listed variant when dates are unavailable). A manually chosen filter, including All events, is preserved on reload while available.
  - Select visible checks every variant in the current filter; Clear selection unchecks all variants, including those hidden by the filter. Both buttons update immediately when checkboxes change.
  - The event selector is left-aligned and table text is centered. Part Number is always the widest column and receives spare width. Other columns fit their content where space permits; narrower windows proportionally shrink the columns to keep the entire table within the available width.
  - Filter by event (the latest event is selected automatically when variants are loaded, until you pick one yourself), select all or clear.
  - The selection always starts empty: it is cleared whenever variants arrive from Home (Load variants, New variant, Update Master Sheet, ...) and after every Create WebFlow jobs run, whether it succeeded or failed. It is not saved between sessions.
- **Settings** module (pinned at the bottom of the sidebar; a module opts in with `pinned_bottom = True`): Theme = System / Light / Dark, saved as `theme` and applied only when you click **Apply** (button at the right, grey while nothing has changed; in Light ordinary action buttons use dark text); System follows the Windows setting, also when it changes. Default is Dark. Selectable navigation (Comparison modes, WebFlow environments, Settings tabs and sidebar items) uses a blue accent background, white text and an accent border when active; inactive items use neutral backgrounds, secondary text and neutral hover highlights in both themes. Muted text (file names, hints), links and drop-down highlights follow the theme. Leaving the page (or closing the app) with unapplied changes asks to **Apply**, **Discard** or Cancel (stay).
- Every push / tool button and drop-down list (and the sidebar module list) shows a hand cursor while it is enabled (`autohub/ui/button_cursor.py`).
- **Settings > Home** also has "Show the WebFlow link column": a read-only "WebFlow Link" column (WF<number>, blue and underlined, double-click to open the job), fixed right after Part Number like No. and Part Number; off by default.
- **Settings > Creation** contains a **WebFlow Environment** selector (Production `https://rb-webflow.bosch.com/app/dashboard` or Acceptance `https://rb-pde-int.bosch.com:8881/app/dashboard`, Production by default; the Base URL is no longer editable and is shared through `autohub.core.webflow_environment`; stored full WebFlow links are never rebuilt from it), Tool version, Routing and the three ECR fields above; Apply saves them together with the other application settings. Creation no longer has a separate Settings button or dialog. Change Reason opens a searchable checkbox dropdown with the four recorded WebFlow options: Correction of a situation, Customer requirement, New supplier / increase of capacity / relocation / standards / others, and Q-Problem. Select all applies to visible search results; multiple checked reasons are saved using `|`. Previous unrecognized settings remain visible and checked so they are not silently discarded. The Settings groups scroll while Apply remains visible.
- **Allocated numbers**: Creation shows **SW Part Number** and **ECR Number** immediately after WebFlow Link. Column widths refresh after loading, importing and filtering, filling the available window width with Part Number widest. Loaded values come from the Master Sheet. After job completion, imported numbers update both Creation and Home and are written as text to existing MG1 columns `AX`/`AW`, or Mx17 main-sheet columns `X`/`Y`, matched by the latest variant's part number. No new Excel columns are added. Write failures are reported explicitly; numbers stay visible and Home enables Update Master Sheet for retry, preserving other edits and pending deletions. Reloading or updating the Master Sheet synchronizes saved Home values back into Creation.
- **Create WebFlow jobs**:
  - Validation: at least one variant is selected, tool version and routing are filled, and all selected variants share the same ECU type.
  - Selenium (Edge) opens the WebFlow dashboard and creates one job per selected variant. The Creation page shows selected/available counts and enables the create action only when variants are selected. Its event filter and "Select visible" action make large batches easier to choose. WebFlow creates at most 10 jobs at once, so larger selections are created in groups of up to 10 (e.g. 24 variants = 10 + 10 + 4); each group is filled and saved before the next group is created, and results stay in selection order.
  - It then fills the General, ECU and Customer tabs and saves each job.
  - A progress window (same as Home) shows each step: starting the browser, opening the dashboard, creating the jobs and filling every job; it ends with the job IDs or the error.
  - After the jobs are created, each variant shows its WebFlow link as "WF<job number>" in the list, and the link is written to the Master Sheet column I ("Webflow No. with Link", MG1 layout) of that variant's request row as a hyperlink whose text is "WF<job number>". Loading the variants reads the hyperlink address back from that cell. The Mx17 layout has no such column, so the window says the links were not written there.
  - Completed job links also update matching rows in Home immediately, without reloading or discarding edits, filters or pending deletions. Enable "Show the WebFlow link column" in Settings > Home to see them. Links remain visible in the session even if writing them to the Master Sheet fails.
  - Selecting variants that already have a WebFlow link asks before creating: **Create anyway**, **Skip them** (only the others are created) or Cancel.
  - A summary of part number and job ID is shown on success.
  - Settings uses **General**, **Home**, **Creation**, and **Diagnostics** tabs, with descriptive groups and theme-aware styling. Creation includes connection/ECR settings and WebFlow Retry; Diagnostics contains Logging and Analysis. Each tab scrolls independently. The persistent footer shows saved/unsaved status, and **Apply changes** saves across all tabs. Home and Creation no longer have separate settings buttons or dialogs.
   - **Retry and resume**: Settings > **Enable automatic retries** switches retries on or off (default on). When unchecked, WebFlow makes one attempt and the attempt-count control is disabled, preserving its value. **Maximum WebFlow attempts** controls total attempts, including the first (1-100, default 5); setting it to 1 also prevents automatic retries. Each retry uses a new browser, waits 5 seconds, and continues from saved progress. Progress is saved to `%APPDATA%/AutoHub/webflow_batch.json` before every server-side effect, so retries never create the batch again, never refill completed jobs and never click Import from pool or ECR Import a second time; an import already clicked without a readable number is reported as a warning. Failures that could duplicate jobs (creation submitted but job IDs unknown) and validation errors are not retried. If AutoHub crashes or is closed mid-run, or all configured attempts fail, the next start asks whether to continue the unfinished work (Yes resumes with the saved settings, retry switch and attempt limit, No discards it). A confirmed resume starts a fresh set of attempts; older saved batches without retry settings use retries enabled and 5 attempts.
  - The browser session is closed after every failed attempt, including the final attempt allowed by Settings, or on app exit. Unfinished progress remains available for resume.

### Form B module

- Receives selected variants from Home and uses Master Sheet values to fill the supplied Form B workbook template.
- Fills up to six variants per block; additional variants get another formatted block below. The exported workbook preserves the template styling and never overwrites the template.
- Uses the Master Sheet checksum in column BA when present. If it is blank, Form B opens the linked WebFlow job, reads the Container `.cnt` CRC32 from Files > Execution Files, and downloads the `.cnt` to calculate an uppercase CRC32 only when WebFlow has no checksum.

### Comparison module

- **Clear Data**, beside **Export Comparison**, clears only the current mode's comparison results and summary/count. XML inputs and the upper variant table, selections, links and statuses remain unchanged. Export is disabled until new results exist; Compare remains available when the retained selections are valid.

- **Modes**: **Master Sheet Compare** is the default and keeps the existing linked-variant workflow described below. **Manual XML Compare** compares one local **Base XML** against one or more local WebFlow Export **Target XML** files without a Master Sheet or browser. **Select XML(s)...** adds targets as compact filename chips that share rows and wrap as the window resizes; duplicate paths (including links to the same file) are ignored. Base uses the same chip style, with only one file allowed. Remove a selected file with its adjacent **×**, or use **Clear All** when multiple targets are selected. Long names are elided; full filenames/paths appear in tooltips. The selected Target count updates immediately, and the chip container uses only the height needed. Compare is disabled without a Base and at least one Target. All files are validated and read-only; Base is parsed once and reused. The shared progress dialog identifies the current Target and overall completion. Invalid files or cancellation retain the previous completed result.
- **Manual XML results**: compare the union of parameter paths from both files, not the Master Sheet scope. Statuses are `MATCH`, `VALUE_MISMATCH`, `MISSING_IN_BASE` and `MISSING_IN_TARGET`; absent paths are marked missing on their respective side. For paths present in both files, blank values use the existing missing-value rules (both blank means `MISSING_IN_TARGET`, never a false match). The shared result table shows **Parameter | Base | Target | Status | Comment**, freezes Parameter, and retains header filters/icons, sorting, clipboard actions, manual Status, Comment editing and status colors. The table follows the action buttons directly without a file or count summary block; selected filenames remain in the file selectors and Target list. Results and reviews remain in memory across filtering, sorting, resizing, file selection, Master data reloads and mode switches; only a new successful manual comparison replaces them. Failed or cancelled runs retain the previous result. Master-specific controls, including **Update Master Sheet**, are hidden and cannot write Master data.
- **Manual XML HTML export**: **Export Comparison** saves all retained rows and reviews with the title **WebFlow XML Comparison Result**, Date, Time, Reviewer, Base/Target XML filenames, Total/Match/Deviation and the five-column manual table. The same offline HTML filters, editable review information, manual-status annotations, Comments, print/PDF styling and signature section are retained. The report uses the files from the completed comparison, even if different files have since been selected, and cannot overwrite either source XML.
- **Multiple Targets**: the same retained result table expands to **Parameter | Base | Target 1: filename | Target 2: filename | ... | Status | Comment**. Its scope is the union of paths across Base and every Target. Each Target value keeps its calculated two-way status and deviations are highlighted individually. A path absent from both Base and a particular Target (but present in another Target) is missing in that Target. Overall Status is `MATCH` only when every Target matches; a common missing status is retained, and mixed outcomes are `VALUE_MISMATCH`. Comments initially summarize deviating targets and can be replaced or cleared. Overall counts use the effective reviewed Status; per-target counts and cell highlights always reflect calculated comparisons over the full shared scope. Header filters, sorting, clipboard edits, manual Status and Comments work with any number of Target columns. The HTML export preserves every Target column/filename, per-cell calculated status, highlights, review overrides, comments, and per-target summary; selecting a single Target retains the original five-column layout and statuses.
- **Exclude Compare Data**: configure parameter/row path prefixes in **Settings → Comparison → Exclude Compare Data** using Add, Edit, Delete or Restore defaults, then **Apply changes**. Each row has a checkbox: checked enables exclusion; unchecked keeps the path saved but ignores it during comparison. Existing entries, newly added entries and restored defaults are enabled by default. Defaults are `Files/` and `Notes/`; deleting every entry disables exclusions. Enabled exclusions always apply to **Manual XML Compare**. They apply to **Master Sheet Compare** only when **Apply to Master Sheet Compare** is checked (unchecked by default). The list, checkbox states and mode option persist in the existing settings store. Normalized paths starting with an enabled prefix are excluded before comparison. They never enter comparison results, parameter/header-filter choices, counts, or HTML exports. New comparisons use the latest saved settings; retained results are not recalculated.
- **Part Number** labels the first data column in both Master Sheet Compare tables, its header filter and the HTML result table. The result table reuses Home's frozen-column overlay to keep Part Number visible during horizontal scrolling, with shared selection, clipboard actions, row heights and filtering. Internal variant identities are unchanged. Manual XML Compare omits Part Number.

- **Result-table clipboard**: select cells with Ctrl/Shift and use Ctrl+C (or right-click Copy/Copy Row) for Excel-ready tab/newline-separated values. Ctrl+V edits only Comments and validated manual Status values; multiline Comment pastes fill consecutive visible rows. Ctrl+X/Delete clear only selected Comments. In the Comment editor, normal text shortcuts work, Enter/focus loss saves and Esc cancels. Comments have a flexible minimum width of 260 px, stay single-line in the table and show full text in tooltips; edits remain in the retained result and HTML export.

- **HTML review information** appears at the top, before compared variants, summary and results. Date, Time, Reviewed by and Approved by are editable inputs initialized from export time/current reviewer (Approved by starts empty). Filtering never resets these fields. Print/PDF displays their current values as plain text with blank Reviewer/Approver signature lines; there is no duplicate approval section at the bottom.

- The selection table fits Select, Variant, WebFlow and Status to content; Base WebFlow Link and Error share the remaining width on load and resize. Checkboxes are centered, and links use the same hover pointer and shared actions as Home/Creation. Horizontal scrolling appears only when the content-sized columns require it.
- Select variants in the **Select | Variant | WebFlow | Base WebFlow Link | Status | Error** table, or use **Select all**, then **Compare selected**. Only variants with valid HTTP(S) WebFlow job links are listed. Each row has an optional editable **Base WebFlow Link**; target links come from the current Master/variant data and are read-only. Across Home, Creation and Comparison, links display blue `WF<number>` text while retaining full URLs internally. Hover shows **Double-click to open. Right-click for options**; double-click opens the stored full URL. Master-sourced links offer only **Copy WebFlow Link** without changing selection or the stored URL. Editable Base cells additionally offer **Edit WebFlow Link** (showing the full URL) and **Clear WebFlow Link**, even when empty. Empty Base cells still accept normal input; after editing, short display is restored and XML export continues using the full URL. Columns remain resizable with horizontal scrolling. Selection labels, progress labels and filters identify configurations by Variant only; SW Part Number remains internal for matching and validation. Home's loaded data and Creation's job links and allocated numbers update this list through the existing module signals; reload Home after editing the workbook externally.
- Comparison uses the existing Edge/WebFlow session class, connection setting and authentication mechanism, with no second login flow. It opens each selected job, waits for the existing job-readiness checks, clicks the ribbon's **Export XML** action once, and captures the completed browser download automatically. No manual browser opening or XML upload is needed.
- Jobs run sequentially in a background worker; each shows **Pending / Exporting Target XML / Exporting Base XML / Comparing / Completed**, skipping **Exporting Base XML** when no base link is set. A target or base export, download, XML or matching failure shows **Failed** and an error in that row without stopping later targets. A failed export session is closed before the next target starts a replacement through the same browser factory. Temporary downloads are isolated per export, and the browser closes after the run. Source controls/navigation are guarded during a run; results are discarded if Master data changes mid-run.
- **Compare selected** immediately opens a modal **Comparison Progress** dialog showing the processed/selected count and percentage (failures count as processed), current variant and operation, and each variant's status/error. **Cancel** lets the active variant finish safely, including its configured base, then skips remaining variants; completed results are retained. The dialog cannot be dismissed while processing. When finished, it shows completed/failed/total counts (plus cancelled count when applicable), changes **Cancel** to **Close**, and the results table refreshes. Cancelled variants are not counted as completed or failed. Results stay in memory after the dialog closes (surviving filter, header-filter, selection, base-link edit and resize events) until the next comparison produces results or the Master data is reloaded. **Export Comparison** (disabled until results exist) saves all stored rows (not just the visible ones) as a self-contained `Comparison_Result_<timestamp>.html` report (title, Date/Time of export, Reviewer from the saved Change engineer setting or the Windows user, compared variants, Total/Match/Deviation summary, and the Variant | Parameter | Master | Base | Target | Status | Comment table, colour-coded with manually changed statuses marked). It works offline with embedded search, Variant/Status filters, Deviations only and Clear Filters ("Showing X of Y parameters"; filtering only hides rows). Printing/PDF hides the controls, repeats the table header, keeps rows unsplit and ends with a Review & Approval signature block without rerunning the comparison or XML export. **Update Master Sheet** (enabled once a variant has compared successfully) asks for confirmation, then writes the exported Target values into the IMPL row (the row below the REQ row) of only the successfully compared variants, only for parameters in the Master Sheet scope; Base values are never written, Target values are first normalized to the Master Sheet's own convention (TRUE/FALSE become Yes/No in Yes/No fields, keeping the existing casing; TP Level `3` or `TP3` is written as `TP3`; multi-value fields whose tokens already match keep the Master's order, e.g. `IMMO6|active`) while the Comparison keeps the raw Target and treats such values as equivalent, missing Target values are skipped, formula cells are left unchanged, and a variant is refused (not written) if its Part Number is missing or duplicated, the next row is not IMPL, or its SW Part Number no longer matches. After saving, the same sheet reader silently refreshes only the updated variants in Comparison, including Master values and REQ column O status (`OK` -> Completed; otherwise Pending). No Home/Load variants workflow runs. Stored results, filters, comments, manual statuses, Base links, selection and table layout remain in place. One success message appears only after save and refresh finish; write/save/refresh failures show one Update Master Sheet error instead. Not supported for the Mx17 layout. Result rows have an editable **Comment** (double-click, or right-click → Edit Comment/Clear Comment) and a manually changeable **Status** (right-click → Change Status/Reset Status); the calculated status is kept internally and shown in the tooltip ("Calculated: X | Manually changed"). Both live in the retained result (not the visible table), are included in the HTML export, and never alter Master Sheet values or the Target values written by Update Master Sheet.
- Only WebFlow `Job/Fields/Field` exports are accepted. XML identity (`General/CustomerOrderNumber` + `General/SoftwarePartNumber`) must uniquely match the selected Master Sheet variant, and an exported JobId must match its link when present.
- Combined results always show **Variant | Parameter | Master | Base | Target | Status**. Master Sheet parameter paths define the comparison/display scope; target-only and base-only XML parameters are ignored. Without a base, statuses remain `MATCH`, `VALUE_MISMATCH`, `MISSING_IN_MASTER` and `MISSING_IN_WEBFLOW` (including blank Master values for sheet-defined parameters). Known Master fields reuse the existing variant payload mappings; unmapped sheet values appear under `Master/<column (label)>`.
- Each selected target is exported first, followed by its own optional **Base WebFlow Link**, using the same browser/export mechanism. Base XML is never shared between variants, even if they specify the same link. Rows with a base use `MATCHES_MASTER`, `MATCHES_BASE`, `MATCHES_BOTH` or `MATCHES_NEITHER`; rows without a base retain two-way statuses and an empty Base column. Base XML need not share the target's variant identity, but its JobId must match that row's base link when present. A base failure affects only its own variant rather than falling back to a two-way comparison.
- The application has no standalone Search field; the result table follows the action row directly in both comparison modes. Manual XML Compare shows selected filenames only in the file selectors and Target list, without an intermediate summary block. The exported HTML report's summaries, search and filters are unchanged.
- Click any result column header/funnel icon (**Part Number**, **Parameter**, **Master**, **Base**, **Target**, **Status**, **Comment**), or right-click the header, to use Home's shared text/value filter popup, including Select all, Clear all and Reset. Column filters combine with each other; gray/blue funnel icons show inactive/active state, including the frozen Part Number header. Values come from the current retained results (including comments and manual statuses), and header filters reset when a new comparison is loaded. Filtering does not alter stored results.
- XML is parsed into parameter-path maps (`Group/Name`; nested values keep their paths and named row identities). Multi-select order is ignored and supported Master aliases / TP levels use the existing WebFlow semantics; other values compare exactly after trimming. Leading zeros, `0` and `false` are preserved. Blank or absent target values never count as a match, including when both references are blank; two-way comparisons mark them `MISSING_IN_WEBFLOW`.
- Invalid links, disabled/missing Export XML actions, failed/timed-out downloads, malformed or ambiguous XML, missing identity values, mismatched job IDs and unmatched or duplicate Master identities show explicit per-variant errors. Changing selection, sources or Master data clears stale results. XML is limited to 10 MiB and rejects DTD/entity declarations.

## Project structure

Dependency rule: `modules` -> `core` <- `services`. Feature modules never import `services/`, and `services/`
never import Qt or `modules/`. `bootstrap.py` is the only place that names concrete classes. The rules are
enforced by `tests/test_architecture.py`; the design requirements are in
[docs/SOLID_REQUIREMENTS.md](docs/SOLID_REQUIREMENTS.md).

```
AutoHub/
├── main.py                       # entry point
├── requirements.txt
├── autohub/
│   ├── bootstrap.py              # composition root: builds services and the module list
│   ├── config.py                 # app name/version, paths
│   ├── core/                     # interfaces and shared, I/O-free code
│   │   ├── module_base.py        # AutoHubModule interface
│   │   ├── capabilities.py       # VariantSource / VariantSink / Closable protocols
│   │   ├── ports.py, records.py  # narrow service interfaces and typed data shapes
│   │   ├── variant_schema.py     # Master Sheet columns shown in the table
│   │   ├── normalizers.py        # pure text normalisers
│   │   ├── webflow_defaults.py   # fixed WebFlow job values
│   │   ├── dialogs.py            # file/message dialog port + Qt implementation
│   │   ├── com.py, workers.py    # COM session per thread, background tasks
│   │   └── settings.py           # SettingsStore protocol + JSON implementation
│   ├── ui/                       # main_window, sidebar, theme
│   ├── modules/
│   │   ├── home/                 # ui (layout), presenter (workflows), service, variant_table
│   │   │                         #   + table_clipboard / table_search / table_filter (row_filter, filter_dialog) / table_actions / frozen_columns
│   │   ├── creation/             # service, ui, variant_checklist, config_form
│   │   └── comparison/           # XML parser | Master mapping/matching | comparison engine | batch service | UI
│   ├── services/                 # I/O adapters (Excel COM, email/xlsx, Selenium)
│   │   ├── common/               # sheet_grid, header_rules, workbook
│   │   ├── MasterSheet/          # session | row_reader | row_writer | variant_builder | webflow_variants
│   │   ├── EcuInfoSheet/         # reader + header-rule parser
│   │   ├── SystemMatrix/         # reader + label-driven parser
│   │   ├── HWInfo/               # reader, parser and per-file-type sources (.xlsx/.eml/.msg)
│   │   ├── KickOff/              # Kick Off Meeting .pptx reader + rule-table parser (power, cylinders, displacement, emission, immobilizer)
│   │   └── WebFlow/              # flat Python package: page adapters, session facade, workflows and helpers
│   │                             #   | components (shared section / drop-down / input / tab / checkbox widgets) | page objects
│   └── resources/                # icons, logo, banner
├── docs/SOLID_REQUIREMENTS.md
├── logs/
└── tests/                        # fakes.py holds the test doubles for Excel, Selenium and dialogs
```

## Requirements

- Windows with Microsoft Excel installed (COM automation through `pywin32`).
- Microsoft Edge and a matching Edge WebDriver (for WebFlow).
- Python packages: `PySide6`, `openpyxl`, `msoffcrypto-tool`, `pywin32`, `selenium`, `olefile`, `python-pptx`, `pytest`.

## Extending

- **New module:** create `autohub/modules/<name>/` with a Qt-free `service.py`, a `ui.py`, and a `module.py`
  (an `AutoHubModule` subclass whose constructor takes its factories). Add it to
  `autohub/bootstrap.py::build_modules()`.
- **New HW info file type:** write a class with `read(path, password) -> list[dict]` and register it in
  `autohub/services/HWInfo/sources.py::default_registry()`.
- **New Kick Off fact:** add one `Rule` to `RULES` in `autohub/services/KickOff/parser.py`, then map its field to a column in `variant_builder._apply_kick_off_info`.
- **New ECU Info Sheet column:** add one `HeaderRule` to `HEADER_RULES` in
  `autohub/services/EcuInfoSheet/parser.py`.
